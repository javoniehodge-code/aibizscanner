# Credible & corroborated — data contract v2.0

Use the [multi-model contract](../../multi-model-data-contract.md), [report standard](../../multi-model-report-standard.md) and section README.

Store source records with type, claim-specific relevance/specificity/independence/evidence assessments, commercial disclosures, limitations and exact supporting passages. Preserve review sample selection, time window, theme counts, negatives, room/context and authenticity limits; do not generate invented counts. Deduplicate syndicated/quoted origins for independent corroboration.

Store shared conclusions for quality, suitability and each significant claim with support level/reason/qualifiers and source/evidence IDs. Assess every provider's response, caveats and disclosed citations separately against that baseline. An opinion or marketing label is not automatically a verified fact. A correct conclusion can lack independent citations; an independent citation can be misrepresented. Keep answer alignment and source support dimensions separate.

Five topic questions in this fixture are not five added hotel decision facts. Counts use topics as the denominator and the source matrix uses cited-at-least-once, not citation frequency. Store all raw provider artifacts and actual citation events. Do not infer absence of source use from no citation.

Source-correction tasks and model-answer changes have distinct verification triggers. For history, preserve prior/current answers, citations, model/configuration, rubric/baseline versions and comparison compatibility. The fixture's missing dates, model IDs, raw API responses and evidence are valid only in explicitly labeled synthetic design mode; reject them from production scoring.
