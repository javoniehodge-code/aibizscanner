# Credible & corroborated implementation

Revised proposal, 24 October 2026. Follow the [shared multi-model process](multi-model-brand-perception.md) and [Section 4 reference](../product/ai-brand-perception/sections/credible-corroborated/README.md).

Build one claim-specific evidence baseline from selected source types. Preserve independent origins, disclosures and actual evidence basis. For reviews, record how the sample was collected, time range, sample size and recurring specific themes including negatives. Do not equate a high average score with supported fit. Verify record/certification matches, exact scope and applicability; absent verification is not proof a claim is false.

Run the same named-business quality, fit and claim diagnostic questions across all four providers with independent web search where actually supported. Preserve the real answers, citations/tool traces and model/settings/date metadata. Grade newly cited sources or flag them unassessed; do not assume source quality from provider selection.

Validate answer claims against the baseline, including missing caveats and overstated credentials. Source grade is shared; answer alignment and actual citation usage are model-specific. Derive the source-by-model citation matrix from actual events, clearly choosing binary presence versus counts. Keep all four providers visible when some runs fail.

Persist prior/current topic answers and source citations. Use compatibility boundaries and explicit single-snapshot limitations from the shared process. Realized recommendation/rank is separate from these diagnostic conclusions. No promise that a correction will cause a particular model to change.

Acceptance: correctly handle mixed guest feedback, no firsthand source, generic/paid coverage, copied lists, missing certification evidence, strong negative reviews, a correct conclusion with only owned citation and an incorrect conclusion that cites a strong source. Validate four-model counts, source-matrix events, synthetic example labels and unchanged-history/no-prior/failure states. Enforce account isolation, bounded costs and evidence provenance.

This documentation does not implement live review collection, provider integrations or a production report.
